# F1. Report residue by call

**Status:** built (tried live on /phone 2026-10-16)

## Spec
As a farmer, I describe my residue by phone in Urdu so someone comes to collect it.

**Build:** the call reaches the ADK voice agent through Telnyx (was Twilio; changed 2026-10-15), or through the browser widget as a fallback. The agent calls a create\_lot tool (residue type, quantity, pickup window, and village and district matched to coordinates from a seeded list), and the API saves the lot.

## Acceptance criteria
- Done when: a spoken call produces a complete lot in the database and the agent reads the details back.

## Decisions
Repo-wide ones are in `../decisions.md` (2026-10-14: internal route group, structured pickup window, recoverable 422s, village matching, auth split, idempotency storage). Story-level:
- A farmer is created on first call from an unknown number (empty name); `farmer_known` means a name is on file.
- `pickup_part` hours: morning 06-12, afternoon 12-17, evening 17-20, Pakistan time (fixed UTC+5, no tz database needed). Dates in the past or more than 60 days out are rejected.
- Quantity must be more than 0 and at most 100 tonnes.
- The lot keeps village coordinates when the village matches (exact or fuzzy, cutoff 0.8), else the district centroid with `place_match="district"` so the agent and admin can tell.
- A replayed create_lot returns the original lot and publishes no second `lot.created` event.

### Spec: report residue without the phone
Voice is skipped for now; the same lot is entered through the web. Constraints are in `validation-rules.md` (section "Report residue by form").
- **API:** `POST /api/lots/mine` (farmer, linked, `Idempotency-Key`); `GET /api/residue-types`, `GET /api/villages?district=`; `POST /api/me/link-phone` (farmer, token phone claim); lots now keep the typed village, district and match (migration 0006) and list with farmer, factory and the quoted farmer payout; admin `POST /api/lots` gets the same field errors.
- **Web:** farmer "Report residue" form and live "Your requests"; verify-phone panel for an unlinked farmer; admin "Add a lot for a farmer" dialog and a live lots table with the factory ranking and override. Live panels are labelled; the other dashboards stay on demo data.
- **Assumptions:** farmers need a verified phone; pickup time is part of the form; unknown villages fall back to the district centre; no edit or cancel; no price preview before submit; a lot with no factory shows "waiting for a factory".
- **Done when:** a farmer submits the form and sees the lot matched to a factory; the admin sees the same lot with its ranking; bad input shows per-field errors; a double submit makes one lot.
