# F5. Check on my requests by phone

**Status:** built (2026-10-16), tests pass (2026-10-17); a live `/phone` call pending

## Spec
As a farmer, I call the line and ask what happened to residue I reported, so I know when it will be collected and paid without going to the website.

**Build:** a fifth agent tool, `check_status`, asks the API for the caller's own recent requests (identity from the call record, never from the model) and the agent explains them in the caller's language.

### API
`POST /api/agent/status` (voice service only, like the other agent routes; read-only, so no `Idempotency-Key`).
- Body: `{"call_id"}`. The farmer comes from the call record (`farmer_id_for_call`); a call with no farmer is 409, an unknown call 404, as for the other agent routes.
- Response: `{"requests": [...]}`, the farmer's 5 most recent lots, newest first, each:
  - `lot_id`, `residue_label`, `quantity_tonnes`, `village`, `district`, `reported_on` (YYYY-MM-DD), `pickup_text` (same wording as the create_lot read-back)
  - `stage`: one of `received` (no factory yet), `matched` (factory found, pickup being funded), `finding_transporter`, `transporter_coming`, `on_the_way`, `at_factory`, `awaiting_your_confirmation`, `confirmed_by_you`, `paid`, `on_hold` (disputed), `rejected`
  - `status_text`: one plain English sentence for that stage, which the agent says in the caller's language
  - `factory_name` when matched; `est_farmer_amount_rupees` (estimate before weighing); `final_weight_kg` and `farmer_amount_rupees` once the factory has weighed it; `rejection_reason` when rejected (then `farmer_amount_rupees` is 0 and no estimate is given)
- No other farmer's data, no phone numbers, no transporter identity.
- Browser calls from the public `/phone` page (number only typed) get only `lot_id`, `residue_label`, `reported_on`, `stage`, `status_text` and `details_withheld: true` (user decision 2026-10-16). A call with no reference is treated the same (fails closed).
- On those calls `get_quote` also answers only for lots made on that same call; any other lot is `unknown_lot` (422), so a lot id heard in the status cannot unlock its amounts.

### Voice
- Tool `check_status()` takes no arguments (the call id comes from the call context). On success it also sends a `status` event to the call screen.
- Instructions: when the caller asks about a request they already made (pickup, payment, where it is), call `check_status`; explain the newest one first; if there are several, say how many and ask which (by residue and date); if there are none, say so and offer to report one. If `details_withheld`, say only the stage, residue and date. Never guess a status.

### Done when
A caller who reported residue earlier asks "mera bhoosa kab uthega?" and the agent tells them the stage of that request (e.g. a transporter is coming, or it is waiting for the factory), matching what the farmer's web page shows.

## Tests
- API (DB-backed): stages for each job state, newest first and at most 5, only the caller's own lots, 404/409 for unknown or unlinked calls.
- API (pure): the stage mapping for every lot status and job state.
- Voice: the tool posts only the call id, passes the result to the model, and emits the screen event; the agent has exactly five tools.
